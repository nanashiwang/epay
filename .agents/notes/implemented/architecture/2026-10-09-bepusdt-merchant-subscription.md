# Agent Note: 商户包月订阅与 BEpusdt 自助接入

Status: implemented

后续扩展：[包月商户自配支付通道](2026-10-09-merchant-payment-channels.md)将零按笔费、共享限额和无平台兜底推广至通用套餐。下文“仅 BEpusdt”范围保留为原专属套餐语义；网关、快照和订阅事务决定仍适用。

## Problem

业务模式是商户按月付费使用 Epay，并自行配置收款网关。需要提供 BEpusdt 接入和上游追踪，同时把平台订阅收入、商户直收本金及其成功凭证分开。

## Existing capabilities and impact

- 复用 [既有 BEpusdt 插件](../../../../plugins/bepusdt/bepusdt_plugin.php)、Channel/Plugin 调度和原支付协议，不嵌入 Go 网关。上游审计基线、只读 remote 和比较命令在 [UPSTREAMS](../../../../docs/UPSTREAMS.md)。
- `pre_group` 的售价、周期、可见范围和 `pre_user.gid/endtime` 继续作为套餐目录与有效期来源；[我的套餐](../../../../user/groupbuy.php) 和 ajax2 的 BEpusdt 套餐分支使用新的事务服务。旧套餐及旧订单保留原有处理。
- [商户收款账号笔记](../feature/2026-10-09-merchant-collection.md) 对应的支付宝基础能力已提交，复用子通道身份、站点外密钥位置、页面样式、通知记录和 worker。支付宝账号字段与 `(uid)` 默认路由仍独立，BEpusdt 以 `(uid,type)` 扩展，避免覆盖支付宝。
- [原生码匹配](../feature/2026-10-09-alipay-native-qr.md) 保留支付宝规则；链上回调不走支付宝轮询或心跳。能力流程笔记无需替代。
- 新建的 GatewayHttp/Secrets/Client 只负责公网连接、加密及 BEpusdt 协议；DbTransaction 封装 PDO 异常/嵌套事务边界，没有另建账务系统。

## Decision

### 商户接入与资金归属

首期采用商户自带 BEpusdt 实例，网络固定 USDT / TRC20、订单法币固定 CNY。商户配置名称、HTTPS 地址、Token、可选地址和超时；不收集钱包私钥或助记词。实例级 Token 不能作为多租户凭证下发。

`bepusdt_account` 扩展 `pre_subchannel`，账号默认停用，依次通过签名回显和真实测试订单回调才可启用。配置改变清除验收状态；最近回调与接口校验分别显示。保存数量、启用数量及新订单均依据实时套餐判断；到期和超限失败时不随机换钱包。停用、归档和历史记录保留可用。

仅商户自助 BEpusdt 订单执行零按笔收费，覆盖比例费、最低手续费及随机加价；本金不入平台余额、不产生订单邀请返利。支付宝及管理员通道保留原有计费。客户向商户付款与平台月费分别流转；平台权益订单禁用商户自助默认路由，回调再次拒绝将自助网关作为平台充值/订阅凭证。

### 订阅事务

新 BEpusdt 套餐的订单保存价格、周期、购买人和套餐快照。`subscription_purchase` 保存请求幂等键，`subscription_event` 以付款订单为唯一键。余额支付的扣款、权益事件和有效期更新是同一事务；外部支付锁定订单和商户，同套餐不同支付累计月份，同一支付不重复生效。

Asia/Shanghai 自然月语义，按实际付款时 `max(旧到期, 当前时间)` 续期，月末钳制到目标月份末日。有效期内不自动折算切换；支付时发现另一个有效套餐，记录已付款待管理员处理，不覆盖已有权益。此分支不触发旧会员邀请返利。

“我的套餐”核对已支付订单及购买人后展示结果，提供最近 20 笔付款/权益记录及原、新到期时间；没有另一份有效期事实来源。当前按月预付，不自动扣款或自动提醒。

### 创建与回调契约

- 创建前落库加密配置快照，以订单级锁串行化并复用已有链接。结果未知进入待核对，不重建相同上游 `order_id`。
- 每次请求校验公网 DNS/IP、TLS、协议/端口、连接 IP、响应大小与同来源收银台 URL；关闭代理和重定向。Token 与订单配置使用站点外的 AES-256-GCM 密钥，绑定 UID，接口不回显明文。
- 金额正值、CNY 固定；JSON 金额为数字。签名遵循 v1.24.2 Go `fmt %v` 的数字格式，包括大额科学计数法，字符串字段保持原值。
- 回调核验签名、订单号、上游交易、法币金额、地址、币额及状态，链上凭证按网络/地址/交易 ID 去重。事务失败回滚，签名有效的异常保留脱敏提示；重复成功不重复入账，乱序超时不降级成功。
- 旧订单根据快照校验，Token 轮换、停用、归档与到期不阻止确认。配置改变后的旧测试回调不能验收新配置。
- 提交到账事务后才返回上游成功，业务站通知单独重试并记录，复用 `CollectionNotify` 和 collection worker。通知是至少一次，业务站仍需幂等。
- 迁移前管理员历史订单没有快照，保留受限旧回调路径并补签名/金额检查；处理完前须保留旧凭据。管理员新 BEpusdt 订单需要迁移和 HTTPS。

### 部署与追踪

[迁移脚本](../../../../scripts/bepusdt-setup.php) 显式追加表、缺失支付类型与停用直收模板，不自动设价、赋权或改变现有钱包。复用既有 PHP/MySQL 与部署脚本。站点外加密文件需持久化挂载并独立备份；本次没有生产操作。

[运行说明](../../../../docs/BEPUSDT_SUBSCRIPTION.md) 记录设置、故障核对、历史订单和回滚边界。独立网关 main、正式版和 PHP 插件分别跟踪，禁止直接合并到 Epay，也没有自动更新或定时同步任务。

操作教程与来源适配见[商户帮助中心](../feature/2026-10-09-merchant-help-center.md)；该文档入口不改变本篇的支付和权限边界。

## Alternatives considered

- **仅启用已有插件**：改动最小，但缺少商户权限、凭据保护及平台权益隔离，不能支撑本次商业模式。
- **商户自带实例**：保留清楚的钱包和网关归属，复用支付协议；代价是商户自行运维网关，平台不能证明其链上监测健康。
- **平台托管网关**：商户只填钱包更易用，但需要隔离实例或受控服务端代理、限流及钱包归属验证，本次不分发实例级 Token。
- **独立订阅/支付系统**：灵活但重复 group、订单与账务；采用现有数据来源加事务和审计表。
- **通用化所有账号表**：长期可减少类型分支，但会扩大当前支付宝匹配/加密迁移范围；只复用身份、页面与通知基础设施，保留 provider 专属配置。

## Consequences

- 商户自助接入与平台月费有独立可信边界，新包月订单具备实时权限、零按笔费和可追溯续期。
- 当前只开放一个网络，没有自动查单补单、链上退款、汇率覆盖或平台托管。创建结果未知、容差付款和缺失回调需要人工核对；不能把后台账面退款当作转账完成。
- 加密文件丢失会使账号及历史快照不可恢复，回滚不能删除扩展表或阻断旧回调。
- 真实链上付款、钱包到账、外部业务通知和生产发布均需单独验收；模拟测试不等于生产收款可用。
