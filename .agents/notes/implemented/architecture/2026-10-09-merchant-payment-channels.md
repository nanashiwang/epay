# Agent Note: 包月商户自配支付通道

Status: implemented

## Problem

商户购买的是 Epay 收款软件的使用期，支付宝、微信等渠道凭据应由各商户持有和配置。仅开放 BEpusdt 不能表达此业务模式，平台渠道自动兜底还会改变收款方。

## Decision

复用 Channel / Plugin、支付类型、子通道身份、会员 gid/endtime 和通知 worker，增加统一商户入口与加密账号、按支付类型默认路由、订单配置快照。管理员配置套餐和支付类型可用范围，只为平台自己的月费收款配置凭据。新套餐选择通用自助权益；旧套餐行为保持兼容，由管理员主动切换。

通用套餐所有自助账号共享数量上限，按笔费为零；未配置、停用、过期或权限不足均不回退到平台渠道。新建订单需实时授权，在途回调按创建快照确认；收款本金不进入平台余额，不能兑换平台订阅或充值权益。

到期任务保留订阅套餐 gid/endtime，避免重置为默认组后恢复平台收款；到期提醒由运营扩展的独立阶段记录和邮件任务提供。Web/API 传给插件的订单字段不完整，授权和测试标志从数据库完整订单读取。凭据、路由、到账与审计使用商户锁串行化，首次快照在订单锁内重新读取，防止并发初始化覆盖。回调仍使用 SDK 验签，新增收款身份、状态、金额及流水唯一性核对。

插件目录采用审查过的契约列表而非将历史插件的管理接口直接暴露。覆盖支付宝 RSA2 公钥模式、微信 V2 与 V3 公钥模式 Native/H5、QQ 扫码、易支付跳转（含支付宝/微信/QQ/银行/京东），并连接现有支付宝原生码与 BEpusdt。未隔离的服务商进件、共享公众号绑定、任意证书路径、退款/转账接口不属于通用凭据表单；界面明确可用模式。微信 V3 私钥与公钥加密保存、仅内存解密，不要求管理员上传证书文件。

## Existing capabilities and impact

- [BEpusdt 与订阅](2026-10-09-bepusdt-merchant-subscription.md)：部分重叠。此前仅 BEpusdt 零按笔费、暂不通用化的范围由此扩展；其网关、快照与订阅事务理由仍成立。
- [商户支付宝原生码](../feature/2026-10-09-merchant-collection.md)：部分重叠。保留票据匹配和轮询；通用套餐扩展其权限与零费规则。
- [原生码匹配](../feature/2026-10-09-alipay-native-qr.md)：不改变匹配算法。
- 能力审查流程笔记与此无冲突，不创建重复流程记录。
- 新[统一入口](../../../../user/channels.php)、[会话 API](../../../../user/channels_api.php)、[账号与快照服务](../../../../includes/lib/MerchantChannel.php)和[审查目录](../../../../includes/lib/MerchantChannelCatalog.php)替代管理员逐户配置；类型、子通道及插件仍使用现有定义。支付宝原生码与通用支付宝账号切换默认时互斥，微信/QQ/USDT 默认独立。
- 受影响入口包括 submit2、支付 API、在线收款、Plugin 调度、到账处理、通知重试、套餐购买/到期、后台模板编辑和商户投诉附件归属检查。部署采用[显式追加迁移](../../../../scripts/merchant-channel-setup.php)，不自动更改旧套餐。

操作教程与来源适配见[商户帮助中心](../feature/2026-10-09-merchant-help-center.md)；该文档入口不改变本篇的支付和权限边界。

## Alternatives considered

- 将管理员表单完整开放：覆盖最广，但插件包含共享文件、公众号、转账和任意外部地址，不能构成租户边界。
- 为每个支付方式另写支付引擎：隔离明确，但重复签名、收银台和订单接口；采用原插件加集中账号与执行边界。
- 让管理员先配置商户模板密钥：代码改动少，但仍依赖管理员逐户配置，不符合自助产品。
- 迁移所有旧账号到一个表：减少分支，但改写支付宝轮询/链上回调历史；保留专用表，共享套餐、入口和通知。

## Consequences

部分老插件的后台能力不是可直接授权给商户的收款接口。支持范围需要在 UI 和文档中列明；模拟测试不能证明真实账号签约产品或资金到账。站点外主密钥及历史快照必须保留。

通用权益需管理员主动给套餐开启；现有平台代收商户不自动迁移。保留三种专属账号存储带来共享限额分支，但避免改写原生码匹配与链上历史。迁移、支持边界和回滚操作见[运行说明](../../../../docs/MERCHANT_CHANNELS.md)。没有生产部署或真实付款。

## Verification

- `tests/merchant-channels.php` 在真实 MySQL 8.0 通过 106 项检查：迁移幂等、租户/CSRF、加密用途、共享账号限额、到期、默认路由失败关闭、Web/API 零最低费和随机费、签名/金额/身份、并发与旧配置回调、平台权益隔离及审计失败回滚。支付宝签名为真实 RSA2 验签，服务端查询使用协议桩。
- BEpusdt 136 项、商户原生码 73 项、原生码匹配 80 项回归通过；PHP / JS 语法和笔记检查通过。CI PHP 8.3 / MySQL 8.0，本地 PHP 8.5 隔离容器。
- 本地真实项目壳验证新增、错误校验、密钥编辑留空、刷新、到期、另一商户隔离、加载失败重试、记录空状态、套餐和原生码相邻入口、桌面与 390px 布局。深色媒体样式通过临时 fixture 强制加载验证。
- 未连接真实支付账号、验证支付机构签约、执行生产迁移或发起真实付款。

运营补充见[包月商户运营与部署闭环](../feature/2026-10-09-merchant-operations.md)：部分重叠，扩展历史返现排除、异常套餐审计、提醒与持久化部署，保留本篇支付与租户隔离规则。
