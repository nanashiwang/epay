# Agent Note: BEpusdt 商户多币种网络

Status: implemented

## Problem

用户的 new-api 业务站需要 USDT、USDC 多网络收款。BEpusdt v1.24.2 交易类型和本地管理员插件支持多链，但商户自配账号固定 TRON 地址及 usdt.trc20，无法直接扩展业务站选项。

## Decision

扩展 [商户订阅网关](../../implemented/architecture/2026-10-09-bepusdt-merchant-subscription.md)，维护显式币种/网络目录，首批 7 条链、12 个组合，与业务站一致。账号通过现有 subchannel → channel → type 绑定不可修改的组合，无新账号表字段；已有账号自然保持 TRC20。一个组合一个账号、独立到账测试、默认路由和套餐名额。

迁移为各类型创建停用直收模板，保留 bepusdt_parent 作为旧 TRC20 模板，新增服务端 bepusdt_parents 映射。浏览器只能选择已准备的类型，不能提交任意父通道。按网络族验证地址，允许留空由网关分配。创建时匹配账号与订单类型、币额地址快照，通知出现显式不符 trade_type 时拒绝；旧通知缺少该字段保持标准协议兼容。

## Related decisions

与商户订阅网关笔记部分重叠：替代首期固定 TRC20 的范围限制，沿用账号验收、订单快照与权益隔离。通用商户通道和运营笔记的共享名额与无平台兜底规则仍适用，不改变支付宝原生码匹配。

## Alternatives considered

- 一账号保存所有链钱包和测试状态：少占名额，但需新建组合级状态、编辑和额度规则，容易误把一次测试用于所有网络；沿用现有按账号验收边界。
- 仅放开网关类型判断：改动最小，但地址仍固定 TRON、默认仍绑定旧类型，不足以闭环。
- 直接合并 BEpusdt 上游：已有插件和稳定版协议足够，不应改变 PHP/MySQL 运行时或引入网关源码。

## Verification

- 隔离 PHP 8.5 / MySQL 8.4 的 BEpusdt 集成套件 346 项通过，新增覆盖全部 12 组合、格式与 Base58 解码长度、模板幂等且不重开停用类型、账号类型不可改、独立测试与默认、错误或缺失类型的创建响应、带错误类型的通知、旧通知无类型字段兼容。
- 通用通道 106 项、原生码 80 项、支付宝商户收款 73 项、运营 42 项与开通流程 12 项回归通过；改动 PHP / JS 语法检查通过。
- 本地项目壳和合成 MySQL：新建 USDC Base、TRON 地址错误拒绝、保存及编辑不回显 Token、组合不可修改、未测试禁止启用、按网络展示订单、390px Solana 下拉和地址提示验收。
- 与 new-api 的显式类型目录通过脚本核对，操作帮助、导航和部署说明同步。
- 帮助中心标题与 catalog 同步；远端门禁发现遗漏的目录标题后补齐，沿用现有帮助套件校验目录、搜索和文章一致性。

## Consequences

复用既有账号和默认路由避免新建一套验收状态；代价是每个组合占一个账号名额，部署需补齐模板。网关 RPC、钱包和实际合约需逐链验收。相同 EVM 地址不能区分网络；收银台显示为准，BSC 等代币不能假定与原生发行版本等价。不迁移生产，不进行真实付款。
