# Agent Note: 保留商户收款与订阅订单凭证

Status: implemented

## Problem

48 小时未付款清理和后台硬删除会留下快照孤儿，导致迟到回调、异常核对和购买幂等丢失原单。

## Decision

复用已有快照、购买记录、原生码账号和通知状态判断保护范围。所有清理入口共享同一 SQL 谓词，订阅及商户直收订单长期保留，旧普通订单仍按原期限清理。后台明确拒绝受保护订单，批量操作先检查整批。

## Related notes

[包月运营](../feature/2026-10-09-merchant-operations.md)部分重叠：保护原有审计基础；支付渠道笔记保留原路由与到账约束，帮助文档无关。

## Alternatives considered

- 延长清理到 30 天：改动小，但仍会在付款争议和历史核查前删除凭证。
- 另建订单归档表：能节省主表，但所有回调与幂等查询都需要跨表，扩大本轮范围。

## Testing

MySQL 14 项检查通过：过期普通单可清理、各种快照与待重试通知保留、管理员单笔与批量删除拒绝。

## Consequences

受保护订单持续增长，后续归档必须保留可查询的完整凭证链。

[支付异常核对](../feature/2026-10-09-payment-review.md)补充查单证据和审计，保留原付款确认边界。
