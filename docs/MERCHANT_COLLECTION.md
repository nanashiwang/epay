# 商户自助收款账号

用户中心入口：`/user/collection.php`。第一批提供支付宝商家账单账号、新增/编辑、原生二维码图片解析、接口校验、监测启停、默认账号选择、0.01 元测试、到账流水核对和逐次业务通知记录。

已新增[通用商户包月模式](MERCHANT_CHANNELS.md)。开启通用权益后，下文的旧套餐费率、固定 10 个账号上限和取消默认恢复平台通道规则由包月规则替代：零按笔平台费、所有自助账号共享套餐限额、到期或取消默认停止该方式收款。原生码匹配与监测约束保持不变。

## 使用流程

1. 填写账号名称、支付宝 UID、原生收款码、已上线应用 APPID、RSA2 应用私钥和支付宝公钥。
2. 保存后点击“校验接口”。通过只说明账单查询权限可用，不证明二维码收款方与应用一致。
3. 启用监测，等状态变为“在线”。点击“测试收款”，付款人核对收款方和金额后自行付款。
4. 测试到账后，按需“设为默认”。该商户的支付宝新订单改用自己的账号。未设置时沿用原通道；停用默认账号会暂停该商户的支付宝新订单，显式取消默认才恢复平台通道。

平台沿用现有用户组费率、订单签名、服务费和资金明细；自助通道强制直收，本金不再计入平台余额。账号测试属于收款测试，独立业务站的异步通知需要另外验收。

## 安装与运行

保留 PHP/MySQL 运行环境。先备份数据库和待更新文件，再执行：

```sh
php scripts/collection-setup.php --apply
```

迁移只新增 `collection_*` 表和一个停用的直收模板，不更改既有账号或默认用户组。模板费率初始为 100%，用户组已配置的费率仍优先。模板不可开启到全站随机通道池，也不要改成平台代收模式。

默认加密文件位于站点目录的上一级 `epay-collection.key`；可用 `EPAY_COLLECTION_KEY_FILE` 配置绝对路径。它必须位于 Web 根目录外，32 字节，PHP-FPM 和监测进程可读，其他用户不可读。首次 CLI 创建权限为 0600，部署管理员应按服务用户设置所有者/组和 0640 权限。数据库与此文件分开备份；丢失后已保存的密钥无法恢复。

Docker 的主密钥持久化、旧容器保全和监督进程见[运营与更新说明](MERCHANT_OPERATIONS.md)。已初始化但密钥缺失时，安装脚本拒绝生成替代文件。

运行 `php scripts/collection-worker.php`，或按实际安装目录/用户修改 `scripts/epay-collection.service` 后安装 systemd 服务。服务每 3 秒查看待确认订单，空闲账号约每 30 秒查一次账；动态读取账号配置，新增账号不需要创建新服务。健康状态由真实查询和心跳计算，超过 120 秒显示离线。接口失败不复制上游原始报文或签名密钥到日志。

同一个服务处理自助账号的业务回调重试，时间沿用首次失败后约 1、3、19、55、115 分钟的间隔序列。既有 `cron.php` 通知任务若已运行仍可继续，接收业务应按订单幂等。通知语义为至少一次；网络成功但确认状态写入前进程终止时可能再次通知。HTTPS 校验证书，仅向公共网络地址发送，不跟随重定向。

## 到账与核对边界

- 付款窗口 5 分钟，自动查询保留 3 分钟宽限。同额占用持续到订单创建后 13 分钟，覆盖迟到查询与歧义保护；不会隐式递增客户金额。
- 只有已展示收银台并取得金额占用的自助订单才是自动匹配候选；并发同金额只允许一个订单展示二维码。未展示的订单不抢占收入。
- 同账号的旧原生码通道也纳入歧义判断。原有插件监测对新模板保守防冲突。
- 已签名收入流水先落库，金额、时间、备注和唯一性校验通过后，流水认领、订单成功、直收服务费在同一数据库事务中提交。业务通知和原有消息通知在提交后处理。
- 流水状态有已匹配、未匹配、金额歧义、超出自动确认窗口。商户可写核对说明，操作记录保留历史；没有“无凭证直接改为已付”的按钮。
- 回调记录包含时间、订单、去除查询参数的地址、HTTP 状态、耗时和结果。失败响应保存摘要指纹，不显示原始内容；按原有签名协议和业务站 `success` 响应确认。
- 接入后开始记录收入；中断后最多追查最近 24 小时，超时收入只进入人工核对，不按当前同额订单认领。更早账单需到支付宝核对。
- 静态码不能证明无备注转账来自哪个网站。使用专用账号，避免同一码跨平台并行收款。原生码不支持付款人身份校验或分账；此类订单继续使用已签约通道。

当前设计针对少量自助账号，每商户上限 10 个。多账号轮询池、独立账号限额、递增金额、批量导入和大规模监测分片不属于第一批。私钥编辑仅在账号停用且无近期在途订单时开放，收款 UID 与二维码不可原地替换。

## 验证和回滚

`tests/merchant-collection.php` 只允许名称匹配 `epay_collection_*test` 的独立 MySQL 数据库。它重建测试表并使用模拟身份/临时密钥；不要指向生产数据库。CI 同时执行原生码旧入口测试。

回滚先停止新订单进入自助账号，保留在途监测直到付款和确认窗口结束；再停新监测服务并还原本次文件。`collection_*` 表、加密文件和审计记录保留，不自动删除。既有旧通道服务和用户组不受迁移改变。
