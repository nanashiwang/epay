# 配置完成后如何验收

收款测试会产生真实支付订单。由你决定测试金额并主动付款；不要把合成测试数据或页面预览当成实际到账。

## 第一阶段：通道测试

1. 在对应通道页面保存自己的配置；完成该入口要求的接口校验或监测上线步骤。
2. 创建小额测试订单，核对收款人、金额、支付网络等信息。
3. 自行完成付款，等待回调或账单监测。
4. 回到本站刷新，确认出现测试到账时间，并核对支付机构中的对应流水。
5. 启用账号，设置该支付方式的默认账号。

通用通道测试金额为 0.01–100 元，BEpusdt 测试为 0.10–100 元。原生码测试还需遵守准确金额及收款窗口。

## 第二阶段：业务网站完整测试

| 核对位置 | 应看到的结果 |
| --- | --- |
| 支付机构或钱包 | 正确账户收到正确金额，有可核对的流水 |
| 本站商户后台 | 同一笔订单已到账，金额与流水对应 |
| 本站通知记录 | 向业务网站投递成功，或有明确失败原因 |
| 业务网站 | 订单已支付，只交付一次商品或权益 |

从业务网站主动发起订单，走顾客实际使用的入口。直接测试收款成功，不代表业务网站通知已经开发正确。

## 还应验证的情况

- 重复通知不会重复发货。
- 付款后关闭浏览器，后台仍能接收通知。
- 未支付订单不会因返回页参数被改动而发货。
- 手机与桌面使用已签约产品时，能走到正确收银台。

出现失败先按[故障排查](troubleshooting.md)定位阶段，再重试；不要为排查而连续重复付款。
