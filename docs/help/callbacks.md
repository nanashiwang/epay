# 支付通知、验签与业务发货

一笔收款有两段通知：支付机构或网关通知本站；本站确认后，再通知你的业务网站。“机构已到账”和“业务网站已处理”需要分别核对。

## 业务网站处理顺序

1. 按本站对应 API 版本验证签名，保留原始参数，不先修改金额或编码。
2. 校验商户归属、业务订单号、支付成功状态，以及金额是否与服务器订单一致。
3. 在数据库事务中把未处理订单更新为已支付，记录本站订单号和交付凭证。
4. 对同一订单重复通知只处理一次，不重复充值、发货或延长服务期。
5. 业务状态持久化完成后，按[支付结果通知文档](/doc/pay_notify.html)返回约定的 success 响应，不夹带页面、调试文字或跳转。

具体字段与签名方法见[签名规则](/doc/sign_note.html)。不要将外部参考站的参数名称直接复制到本站通知代码。

## 通知地址需要满足什么

使用业务网站可由公网访问的地址；自助订单通知只访问公共网络，HTTPS 会校验证书，不跟随重定向。内网地址、登录页面、证书错误或需要跳转的地址会导致失败。

## 查看和重试

在对应收款入口的“通知记录”中查看通知时间、订单号、目标地址、HTTP 状态、耗时和结果。先修复业务网站问题，再对已到账业务订单使用“重试通知”。

后台会独立重试失败通知，因此同一通知可能送达多次。用户手动重试也可能与后台重试重叠，业务端必须幂等。

## 为什么返回页不能证明成功

顾客可能关闭页面、网络中断，也可能手工修改 URL。浏览器返回仅用于展示，不能替代服务端验签和本站已支付订单记录。
