# 商户包月与 BEpusdt 自助直收

商户入口为 `/user/bepusdt.php`，套餐购买和续期在 `/user/groupbuy.php`。BEpusdt 是商户自行部署的独立服务，Epay 不持有钱包私钥。开放 CNY 订单、USDT / USDC 多网络付款；商户支付平台月费，客户支付到商户钱包。

通用包月模式已扩展到支付宝、微信等[商户自配支付通道](MERCHANT_CHANNELS.md)。开启通用权益后，下文“仅 BEpusdt 零按笔费”和“取消默认恢复平台通道”的旧套餐描述不再适用：所有自配账号零按笔平台费、共享总限额，取消默认或到期不会恢复平台收款。BEpusdt 专属网关和回调规则保持不变。

## 开通与配置

保留现有 PHP 8.3 / MySQL 和部署方式。部署管理员先备份数据库、收款加密文件，再在对应站点的 PHP 运行环境执行：

```sh
# 已安装商户自助收款基础设施时跳过第一条
php scripts/collection-setup.php --apply
php scripts/bepusdt-setup.php --apply
```

迁移新增 `bepusdt_*`、`subscription_*` 表、缺失的下表 12 个币种/网络类型，以及停用的商户直收模板；已有部署也需重新运行 `bepusdt-setup.php --apply` 补齐模板；重复运行不重复创建，不重开管理员已停用的支付类型。原 `bepusdt_parent` 继续指向 TRC20，`bepusdt_parents` 保存各组合模板。不自动设定售价、给现有用户开权益或变更已有默认通道。模板必须保持停用、直收、插件为 `bepusdt`，不能放进平台随机收款池。

沿用 `EPAY_COLLECTION_KEY_FILE`（默认站点上一层的 `epay-collection.key`），32 字节并位于 Web 根目录外，PHP 服务用户和 CLI 用户均须可读。Docker Compose 已配置站点外持久卷；旧版首次升级先按[主密钥保全步骤](MERCHANT_OPERATIONS.md)迁移旧文件，不能依赖容器内临时文件。新账号 Token 和订单配置快照以 AES-256-GCM 加密并绑定商户 UID。独立备份密钥；更换外部加密文件需要单独迁移旧密文，不能直接覆盖。

管理员在“用户组”编辑页开启“BEpusdt 自助收款”，设置 1–20 个账号限额、套餐售价、上架/可见范围和 1–120 个月周期；普通月费产品使用 1 个月。原有支付类型关闭规则继续有效。`group_buy` 开启后，`reg_pay_uid` 对应的平台商户需要有效的平台通道。价格由运营者决定，代码无默认收费标准。

本次零按笔服务费仅作用于商户自助 BEpusdt 订单，覆盖比例费、最低手续费和随机加价；直收本金不增加平台余额，也不产生此类订单返利。支付宝自助收款和管理员旧通道保留原有收费规则。新订阅购买使用独立权益流水，不触发旧会员邀请返利。


## 币种与网络

| 网络 | USDT | USDC |
| --- | --- | --- |
| TRON / TRC20 | `usdt.trc20` | — |
| Ethereum / ERC20 | `usdt.erc20` | `usdc.erc20` |
| BSC / BEP20 | `usdt.bep20` | `usdc.bep20` |
| Polygon | `usdt.polygon` | `usdc.polygon` |
| Arbitrum One | `usdt.arbitrum` | `usdc.arbitrum` |
| Base | — | `usdc.base` |
| Solana | `usdt.solana` | `usdc.solana` |

每个组合对应一个账号、独立测试和默认路由，各占一个套餐名额。同一实例的 HTTPS 地址和 Token 可复用，保存后不能改币种与网络，需要新增另一组合。网关需配置该网络钱包、扫链服务和实际代币合约；同名代币在不同网络可能是跨链版本，不保证可互换。地址留空使用该网络钱包池，非空时验证 TRON / EVM / Solana 格式。地址格式通过不代表该链实际可收款。

## 商户使用

1. 选择币种与网络，新增名称、公网 HTTPS 地址、API Token、可选的该网络收款地址和付款窗口。支持 HTTPS 443/8443；不支持私网地址、转发跳转和自签名证书。
2. “校验接口”通过网关签名回显检查配置，不创建链上交易，也不证明实际钱包到账。
3. 主动创建人民币 0.10–100.00 元测试订单，到网关收银台按指定网络、地址和**精确币额**自行转账。Epay 仅在校验到账回调后标记测试通过。
4. 启用并设为默认。每个币种与网络的默认账号分别保存，与支付宝默认账号互不影响。停用或到期会暂停新交易；显式取消默认才恢复原平台通道选择。
5. “支付订单”保留人民币金额、币种与网络、实际币额、系统订单、网关订单、地址和链上交易；“通知记录”可查询每次业务站通知及重试结果，“操作记录”保存配置变更行为。接口永不返回 Token。

数量限制包含未归档的 BEpusdt 账号，启用数量再次按套餐校验。套餐降级导致超限时暂停该商户新直收交易，需要停用超额账号，不随机切换钱包。到期仍可查看记录、停用、取消默认、归档及重试业务通知。

## 订阅与支付边界

自然月预付，按实际到账时的 `max(原到期, 当前时间)` 增加购买月数，时区 Asia/Shanghai。月末钳制，例如 2028-01-31 15:20 续一个月至 2028-02-29 15:20。并发支付累加月份，同一订单只生效一次。余额扣除、权益事件和有效期更新在同一事务。

会员费、余额充值等平台权益订单不得采用商户自助 BEpusdt 或支付宝账号；商户自己的 Token 不构成平台已收款的证据。付款人不能靠 `?ok=1` 取得成功提示。有效套餐切换不自动折算；支付期间被管理员切换到不同有效套餐的订单进入“已付款，套餐变更待管理员处理”，保留原权益及付款记录。

本功能不自动扣款；[套餐运营扩展](MERCHANT_OPERATIONS.md)提供站内及邮件到期提醒。普通历史会员订单仍走原有处理，新开启 BEpusdt 的套餐订单才进入新的事务续期路径。

## 网关契约和故障处理

适配审计基线为 BEpusdt v1.24.2；追踪方式见 [UPSTREAMS](UPSTREAMS.md)。没有嵌入 Go 扫链进程或复制上游服务代码。

- 创建前持久化加密配置快照，按 Epay 订单串行化创建，并复用已取得的未过期链接。同一个 `order_id` 在上游会重建交易，因此请求超时或响应不匹配时标记“待核对”，绝不盲目重建。
- 网关地址在每次请求时校验 DNS、公网 IP、证书和连接目标；禁止重定向、代理转发、超大响应。返回收银台只允许同一 HTTPS 来源。
- 创建响应必须返回与请求一致的 `trade_type`；不一致或缺失时进入待核对。v1.24.2 标准通知不含该字段，通过已锁定的订单快照匹配；通知若带此字段必须与快照一致。回调验签后严格绑定订单、上游交易、法币金额、地址、币额与成功状态；`block_transaction_id` 按网络和收款地址去重。错误币额、多付/少付、歧义交易不自动认领。
- 配置修改、停用、归档和套餐到期不改变历史交易的签名密钥。并发回调只有一次入账，提交数据库后才返回 `ok`；商户业务站通知独立重试。
- `collection-worker.php` 复用既有通知记录及退避机制，无需第二个 worker。BEpusdt 到账依靠网关回调，不使用支付宝心跳判断“离线”。需要监控网关自身扫链状态及 Epay 通知积压。
- 网关返回“待核对”或回调丢失时，管理员需对照 BEpusdt 原订单、链上凭证与 Epay 订单处理；当前没有可信的自动服务端查单、自动补单或强制标付按钮。不要直接重放创建接口。确认没有付款并关闭网关旧单后，才让客户从业务站重新下单。
- 没有自动链上退款。后台账面退款不代表钱包转账，应通过独立人工流程核对并保留记录。

管理员已有 BEpusdt 通道的新订单也需要先完成迁移，并遵守 HTTPS 和快照校验。迁移时间以前、没有快照的管理员订单保留旧回调入口，增加签名、订单与金额校验；它们没有完整的旧配置快照，处理完前不要轮换其 Token 或收款地址。

回滚时先停止新订单，保留当前回调代码、数据库表和外部密钥直到在途订单处理完成。不能直接删 `bepusdt_parent` 配置或扩展表，否则会中断历史订单确认和通知。自动恢复未知创建结果、平台托管、汇率覆盖、自动扣款均是后续能力。

## 验证

`tests/bepusdt-subscription.php` 在名称为 `epay_bepusdt_*test` 的独立 MySQL 数据库重建测试表，使用模拟账户、临时密钥与协议桩。覆盖真实支付 API 的最低费/随机加价绕过、月末、余额事务、并发续期/回调、金额/签名/地址/币额、重复链上交易、所有权、Token 轮换、过期与通知审计。CI 使用 PHP 8.3 / MySQL 8.0，并继续执行支付宝原生码回归；商户支付宝工作流也独立运行。

本地页面验收使用模拟数据与真实项目页面，包括新增、错误输入、Token 不回显、到期、加载失败、普通用户隔离、套餐余额续期、记录和 390px 窄屏。深色媒体样式通过本地 fixture 强制加载核对。

代码测试和接口校验均不替代上线验收：配置实际套餐和网关后，由商户主动完成一次真实小额转账，分别核对钱包、Epay 订单、独立业务站通知。此次开发没有部署生产、迁移生产数据库或发起真实转账。
