# 支付宝原生收款码

`alipaycode` 保留普通转账和转账确认单，另提供「原生收款码（账单确认）」模式。它展示账号自己的 `https://qr.alipay.com/…` 收款码，付款人填写收银台金额，后台通过已验签的账务查询确认收入。它不代表已经签约官方网站支付产品，也不保证每笔付款通过支付宝风险校验。

## 配置和运行

在已有通道配置中填写应用 APPID、支付宝公钥、应用私钥、收款账号 UID，以及解码后的原生收款码地址；支付类型选择原生收款码。二维码必须属于账务查询对应的收款账号。非第三方应用的授权 token 留空。修改后重启该通道原有的 `php server.php <通道ID>` 守护进程。

网页、API 和直接付款路由共用同一收银台。五分钟内扫码并准确输入金额，完成后返回页面等待确认。收银台不会给静态收款码附加未经支持的金额参数，也不会自动加价。启用了 `alipay_wappaylogin` 付款人身份检查时，本模式拒绝展示收款码，应改用支持该检查的签约支付通道。

## 到账匹配边界

- 只接受收入流水、正数分金额、支付宝流水号和有效付款时间。
- 完整订单号备注（兼容旧前缀）优先；无备注时，按相同收款账号、金额和订单五分钟付款窗口匹配唯一订单。非空且无法识别的备注不会降级按金额处理。
- 判断歧义时包含已完成订单，以及相同收款账号在其他 `alipaycode` 通道上的订单。参数化父通道保守纳入；存在同额冲突时不自动入账。
- 查询覆盖最近八分钟，允许在付款窗口内发生的收入稍后被查到。超时后发生的付款不自动确认。
- 确认前持有收款账号的 MySQL 命名锁，重新检查订单状态、通道、金额及流水重复使用。通过既有 `processNotify` 执行入账和商户通知；前端只能查询结果。

**无备注流水不能证明来源网站。** 收款账号应专用于本系统，不要同时用于其他平台和线下同额收款。静态码无法撤销已经保存的二维码，也无法阻止客户填错金额或超时付款。金额冲突、站外收入、超时及备注异常均需保留账单后人工核对；高并发场景应使用提供明确订单标识的官方签约接口。

## 验证

```sh
php tests/alipay-native-qr.php
bash .agents/verify-notes.sh
```

测试使用虚拟账单和内存数据库替身，不读取配置、连接支付接口或发起付款。它覆盖匹配条件、歧义、重复流水、锁释放、页面过期、旧入口和身份检查兼容。真实验收仍须付款人核对收款方完成付款，并核验订单入账与实际业务回调。验收前保持新通道关闭，通过后台单通道测试进入收银台。
